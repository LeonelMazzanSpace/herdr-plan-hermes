Herdr desde Telegram

Creá y despachá una orquestación desde Telegram. Hermes Agent recibe tus mensajes y se los pasa al orquestador Claude Code; el orquestador te contesta por un webhook.

Cómo funciona

Ida: tus mensajes y comandosVuelta: preguntas e hitos del orquestador
  • Hermes solo enruta. Reenvía tu texto literal con el prefijo [telegram user=… msg=…]. No decide, no aprueba y no responde permisos.
  • El orquestador es el de siempre. Con HERDR_TG=1 te pregunta y te avisa con notify-telegram.sh en vez de hacerlo por su chat.
  • La vuelta no gasta tokens. El webhook entrega el mensaje directo en Telegram (--deliver-only).

Instalación

Todos los comandos se corren desde herdr-plan-hermes/, en el host que queda prendido.

1 · Herramientas

# Claude Code
curl -fsSL https://claude.ai/install.sh | bash
claude                        # login la primera vez; después /exit
# Herdr y su integración con Claude
curl -fsSL https://herdr.dev/install.sh | sh
herdr integration install claude
# Skills de Herdr
pnpm dlx skills add herdrdev/herdr --skill herdr -g
pnpm dlx skills add aerain/herdr-agent-orchestration -g -s herdr-agent-orchestration -a claude-code
# Hermes Agent
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
hermes model                  # un modelo chico alcanza: solo enruta
# Utilidades del script de aviso
sudo pacman -S --needed jq openssl curl     # macOS: brew install jq

Superpowers se instala adentro de Claude Code:

/plugin install superpowers@claude-plugins-official

Listo si claude --version, herdr --version y hermes doctor responden, y herdr integration status dice claude: current.

2 · Herdr sin terminal

loginctl enable-linger "$USER"
mkdir -p ~/.config/herdr ~/.config/systemd/user
cat setup/herdr-config.toml >> ~/.config/herdr/config.toml   # si ya tenés [server], agregá solo las 2 claves
cp setup/herdr.service ~/.config/systemd/user/                # completá PATH y la ruta de herdr
systemctl --user daemon-reload && systemctl --user enable --now herdr.service

Listo si herdr workspace list responde desde una terminal fuera de Herdr.

3 · Bot de Telegram

Creá el bot con @BotFather (/newbot) y sacá tu ID numérico con @userinfobot.

hermes gateway setup          # Telegram: token y TELEGRAM_ALLOWED_USERS=<tu ID>
hermes gateway install && hermes gateway start

Listo si /whoami en Telegram te muestra como permitido.

4 · Webhook de vuelta

# en ~/.hermes/.env: WEBHOOK_ENABLED=true y WEBHOOK_PORT=8644
hermes gateway restart
hermes webhook subscribe herdr-events \
  --prompt "[{run}] {kind}
{text}" \
  --deliver telegram --deliver-chat-id "<tu chat id>" --deliver-only
mkdir -p -m 700 ~/.config/herdr-telegram
umask 077 && printf '%s' '<secreto que devolvió subscribe>' > ~/.config/herdr-telegram/webhook.secret

Listo si hermes webhook test herdr-events --payload '{"run":"test","kind":"event","text":"hola"}' te llega.

Uso: qué ejecutar

Todo desde Telegram. La primera vez, con un repo de juguete y un spec de dos tareas.

Vos mandásTe llega
1. /herdr nuevo ~/ruta/repo con el spec adjuntoQ-1: resumen del plan y decisiones abiertas
2. "Aprobado", o tus correccionesEl plan guardado, o un Q nuevo si cambió
3. /herdr ejecutarQ-2: tabla de stack, modo de permisos, suspensión y ClickUp
4. Tus respuestas a esas filasUn event por cada tarea verified, y un blocked si algo frena
5. /herdr status cuando quierasAvance, bloqueos y próximo paso
6. Nada: esperádone: resultado, checks y trabajo pendiente

Además: /herdr ver muestra las últimas líneas del panel, /herdr pendiente las preguntas abiertas y /herdr parar frena todo sin borrar nada. Push y PR se piden aparte, nombrando la rama.

Qué cambia respecto de herdr-plan

herdr-plan no se toca. La copia solo se comporta distinto con HERDR_TG=1.

  • Skills renombrados con -hermes, para convivir con los originales.
  • executing: sección "Telegram channel", chequeo del canal en el preflight y systemd-inhibit en Linux.
  • writing: el resumen y la aprobación del plan salen por Telegram.
  • Nuevos: notify-telegram.sh, el skill de Hermes y setup/.
  • Mismo formato de plan y mismos scripts de paquetes.

Seguridad

  • TELEGRAM_ALLOWED_USERS con tu ID. Nunca *.
  • Solo los repos de HERDR_TG_REPOS. Tu texto pasa por un archivo, nunca concatenado en un comando.
  • Secretos en ~/.hermes/.env y en un archivo 0600. El puerto 8644 no se expone fuera del host.
  • Push, PR y merges a ramas compartidas solo si lo pedís nombrando la rama.

Por decidir y por verificar

  • Tuyo: qué máquina queda prendida, y qué modo de permisos usa el orquestador sin nadie en la terminal (recomiendo auto con un allowlist).
  • Lo de Hermes no se probó en vivo (no está instalado acá). hermes gateway install sale de guías de terceros: confirmalo con hermes gateway --help.
  • Firma del webhook: la doc no muestra un ejemplo. Si la prueba del paso 5 da 401, ajustá el formato.
  • herdr agent prompt con el orquestador trabajando: no está documentado. El puente espera a que quede libre.
